02 · Memory types

Two separate dimensions: memory type and storage

Memory type is what the memory holds: episodic (past events), semantic (facts and knowledge) or procedural (how to act). Storage backend is how it is kept and retrieved: a vector store, a profile database, a knowledge graph, summaries, skill files or model weights. The two are independent. Episodic memory can be raw logs or a vector index of past interactions, and procedural memory can be skill files or vector-indexed experiences. The matrix uses memory type for rows. Storage is a tag on every paper.

Memory also moves between types. Summarization turns episodes into semantic facts, and skill distillation turns episodes into procedures. These transitions are attack channels in their own right (see Gap 2). The live context window (working memory) is out of scope here because it belongs to the prompt-injection literature. A memory attack starts when content persists.
